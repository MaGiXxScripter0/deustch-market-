# Управление категориями — дизайн

## Цель

На странице `/admin/kategorien` администратор может быстро найти категорию и безопасно удалить её. Товары удалённой категории сохраняются без категории и остаются доступными для поиска и в общем ассортименте.

## Поведение в интерфейсе

- Над списком категорий отображается клиентское поле поиска. Поиск выполняется сразу при вводе, без запроса к серверу, по `name_de`, `slug` и `description_de`, без учёта регистра.
- При отсутствии результатов отображается понятное пустое состояние. Создание, редактирование и переключатель активности существующей категории сохраняют текущую логику.
- Для каждой категории доступна кнопка «Kategorie löschen». Нажатие открывает модальное окно с названием категории, числом привязанных товаров и пояснением, что товары сохранятся без категории.
- В модальном окне администратор должен напечатать точное отображаемое название категории. Кнопка удаления заблокирована до точного совпадения; отмена, Escape и клик по затемнению закрывают окно без изменений.
- Во время отправки форма блокируется. Успешное удаление закрывает окно и обновляет список. Серверная ошибка остаётся в модальном окне и не скрывает введённый текст.
- В админском каталоге товаров появляется фильтр «Ohne Kategorie», чтобы быстро найти и назначить товары, отвязанные при удалении категории.

## Данные и серверная логика

- В новой миграции `products.category_id` становится nullable, а его внешний ключ получает `ON DELETE SET NULL`. Удаление категории больше не удаляет и не блокирует её товары.
- Серверный action принимает UUID категории и строку подтверждения. Он доступен только администратору, повторно загружает категорию, сравнивает её точное `name_de` с введённым текстом и удаляет строку категории только при совпадении.
- База данных отвязывает товары через ограничение `ON DELETE SET NULL`; отдельное клиентское массовое обновление не используется.
- Action обновляет кэш каталога и повторно валидирует страницу категорий, страницу товаров и публичный ассортимент/поиск.
- Модель каталога допускает товар без категории: на публичных экранах такой товар входит в общий список и результаты поиска, но не появляется в списках и страницах конкретных категорий. В админском списке он отображается с меткой «Ohne Kategorie» и поддаётся фильтрации.

## Компоненты и границы

- Серверная страница категорий продолжает загружать данные и передаёт сериализуемый список в новый клиентский компонент управления списком.
- Клиентский компонент владеет только поиском, открытием/закрытием модального окна и состоянием подтверждения удаления. Существующая форма редактирования категории остаётся отдельным компонентом.
- Серверный action остаётся единственной точкой выполнения удаления и авторизации.
- Выделенный чистый helper формирует/фильтрует административные товары по категории, включая значение отсутствующей категории, и покрывается unit-тестами.

## Ошибки и защита

- Предпросмотр без прав администратора не позволяет открыть или подтвердить удаление.
- Несовпадение имени, невалидный UUID, исчезнувшая категория, отсутствие Supabase или ошибка базы возвращают безопасное сообщение без удаления данных.
- Модальное подтверждение — защита интерфейса; серверная проверка имени и прав — обязательная защита от подмены формы.

## Проверка

- Unit-тесты покрывают фильтрацию административного списка, включая поиск и товары без категории, а также правила, по которым подтверждение удаления доступно только при точном совпадении названия.
- Проверка типов, линтер и полный набор тестов должны завершаться успешно.
- Ручной сценарий: найти категорию, открыть удаление, проверить неактивную кнопку при несовпадении, подтвердить точным названием, убедиться, что категория исчезла, а её товары находятся в «Ohne Kategorie» и доступны в общем ассортименте.
